Features

What is Rak?

One frontend, two backends. Everything below ships in the compiler and works in the IDE.

|>

Pipeline |>

Chain calls left-to-right. data |> parse |> load reads top-to-bottom like a sentence.

/\d+/

Regex literals

Write /\d+/g inline. A / after a value is division; everywhere else it is a regex.

0x89

Binary patterns

Match byte slices by magic number: [0x89, 'P', 'N', 'G', ..]. Built for PCAP and file sniffing.

impl

Traits & protocols

Implement Display, Iterable, Index. They drive dump, for, and obj[key].

C

Systems stdlib

FFI, memory-mapped files, raw sockets, async I/O, DNS/TLS/PCAP parsers, macros, and modules.

~6x

Bytecode VM

The VM runs the same code about six times faster than the tree-walker. Compare with rakc bench.

key

VPN toolkit

X25519 key exchange, ChaCha20-Poly1305 AEAD, HKDF key derivation, tunnel framing, and an encrypted UDP transport.

cite

Evidence provenance

Every decoded value can carry where it came from, and a report can cite it. Chain of custody, in the type system.

IDE

Desktop IDE

A Tauri + Next.js IDE with a real-time explorer, smart completion, an in-editor docs panel, and a GUI designer.

One language, two engines

The backends agree

Rak ships a tree-walking interpreter and a bytecode VM. A gate in the test suite compares their builtin registrations name by name, and the gap is zero: every builtin both engines expose, they expose on both.

run

The interpreter

A tree walker over the AST. It is the reference implementation: contracts, evidence provenance, closures and the GUI all run here first.

vm

The bytecode VM

A stack machine with the same builtin surface. Channels, TCP, WebSocket, DNS and futures are native there too, not a subset.

=

The gate

A structural check reads both registration tables and fails on any name they do not share, plus behavioural tests run the same program on each.

Remaining gaps

Postconditions and closure capture of locals run on both backends now. The ones that remain are written down, not hidden.

Workflow

From nothing to a shipped tool

Install a release or build from source, then stay in one toolchain.

01

Install

A native installer edits your PATH, sets RAK_PATH, and records every action for clean uninstall.

02

Write

One file or a package tree. The IDE, the CLI, and the language server all read the same source.

03

Run

rakc run on the interpreter, rakc vm on the bytecode, rakc build to a native binary.

04

Ship

oyvey vendors dependencies into packages/ and locks every revision with a checksum.
