Rak language reference

Rak is a programming language for security research, OSINT, and systems work. Hex is a real type, syntax reads like English, and the standard library covers networking, HTML, crypto, and the low-level work you'd otherwise hand-roll. Two backends — a tree-walking interpreter and a bytecode VM — share one parser, so a script that runs on one runs on the other.

2 backends 10 feature families 68 unit tests MIT
Two backends, one language

rakc run is the interpreter — every feature works there. rakc vm is the stack-based bytecode VM, roughly 6× faster on compute-heavy code. Use rakc bench to compare, rakc build for a standalone executable.

Syntax overview

Rak uses English keywords and newlines as separators. Hex is a real type, not a formatting trick. Statements inside blocks don't need semicolons; top-level statements do.

Variables

Bind with let. Add mut if you'll reassign later. Without mut, reassigning is an error.

Functions

Closures capture their definition environment (lexical scoping), so recursion and higher-order functions just work. Declarations can be async (§ Async & futures) and pub/export-ed (§ Modules).

Control flow

Structs, enums, and match

match arms need a trailing comma. Patterns support literals, identifiers, tuples, arrays, struct fields, Some/Ok/Err, ranges, byte lists (see § Binary patterns), and | alternatives.

Part 1 · Language mechanics

Language features

Pipeline |> shipped

The pipeline operator threads a value into the next call, so data flows left-to-right instead of nesting inside-out. It's implemented as a parse-time desugar, so both backends evaluate it for free — no new bytecode.

The rule

x |> f becomes f(x), and x |> f(a, b) becomes f(x, a, b) — the left value is prepended as the first argument. Chaining is left-associative: data |> parse |> load is load(parse(data)). It binds looser than assignment, so let y = x |> f takes the whole pipeline as the value.

Internally |> only exists at parse time — rakc parse prints a plain Call node. The |> token (PipeGt) is distinct from bitwise |, and nested pipelines must be parenthesised.

Regex literals shipped

Write a regex inline with /pattern/flags. Lexing is context-sensitive: a / after a value is division, anywhere else it starts a regex — so let r = /\d+/g and a / b both parse correctly.

Flags

i case-insensitive, m multi-line, s dotall, x extended, g accepted (find-all is global anyway). A literal / must be escaped as \/; // would be a line comment. Literal / inside a character class [a/b] is fine.

Invalid patterns raise invalid regex /pat/flags at runtime (interpreter) or compile time (VM) — never a panic. The VM compiles the regex once at compile time as a constant.

Binary pattern matching shipped

Match a bytes (or mmap-slice) value against a list of byte literals. A trailing .. matches the rest, so you can sniff magic numbers without knowing the full length.

Byte literals

Inside a bytes pattern, literals can be hex (0x89), decimal (216), or a char ('P'). Each is bounds-checked to 0–255 at parse time; out-of-range hex or a non-ASCII char is a parse error. A pattern with .. matches the rest; without it the lengths must be equal. Bindings inside byte patterns aren't supported — binary matching is for inspection, not deconstruction.

Always comma-terminate match arms

A missing comma lets the parser treat the next arm's [ as an index into the previous body — diagnosed as Expected RBracket, found Comma. Not a runtime surprise, but it bites.

Binary pattern matching is interpreter-only. On the VM a Bytes pattern returns VM match does not support pattern — a clear error, not a wrong answer.

Traits & protocols shipped

Traits are the language's protocols. Implement one on your type and the built-in syntax uses it automatically. The receiver is passed as the first argument of every method — there's no self keyword, so name it whatever you like.

TraitMethodDrives
Displayfmt(self)dump, dump x, "file"
Debugfmt(self)trace
Iterableiter(self) -> arrayfor x in target
Indexindex(self, key)obj[key] read
IndexMutset(self, key, value)obj[key] = v write
IndexMut is functional

Rak values are cloned on read, so mutation is functional: set must return the updated container and the interpreter writes it back to the target. If a struct has a field and a method with the same name, the method wins for obj.name(...); reading obj.name still gets the field. Iterable::iter must return an array.

Traits are interpreter-only. On the VM, obj.method(...) resolves via FieldGet and errors with cannot call non-function — the documented VM subset.

Macros & constants shipped

AST-expanding macros with $param placeholders, macro_rules!-style. Macros expand in the frontend, so both backends see the expanded code — the interpreter evaluates the spliced body, the VM compiles it in place at compile time.

Semantics & limits

Macros are non-hygienic: a let t = $a in a macro body introduces t in the caller's scope, and expansion isn't depth-capped. Missing macros and arity mismatches give clear errors (undefined macro 'foo!', macro 'foo!' expects N args, got M). Fragment kinds (:expr / :literal / :ident / :tt) are accepted but treated as expressions; $(...)* repetition and macros that expand to raise on the VM are follow-ups.

Modules: imports & exports shipped

Python-style modules with explicit pub/export, name-based resolution, from ... import, directory packages, import-once caching, and circular-import support. Works on both the interpreter and the bytecode VM.

Resolution order

Name-based imports search importer_dir, then ./packages/, then RAK_PATH, for <name>.rak then <name>/init.rak. Missing modules report the search path; missing exports report 'x' is not exported. Imports are cached by canonical path (import-once), and circular imports return the partially-built module — Python semantics.

VM subset

import pkg.sub nested-package access is interpreter-only (the VM's flat-globals architecture can't isolate per-module scopes — use from pkg.sub import x). pub struct/pub enum don't export on the VM; use pub let/fn/const/macro for cross-VM modules.

Part 2 · Systems & OSINT

Systems & security capabilities

Foreign Function Interface shipped

Call C functions two ways: declarative extern "C" bindings with typed signatures, or the dynamic loader with ffi_load / lib.call. Pointers are opaque u64 addresses — dereferencing is always explicit.

How calls marshal

lib.call(symbol, args) takes the args as a single Rak array (elements are marshalled to C; [] means none) and returns an i64. The declarative extern form uses the declared return type for proper unmarshalling and supports ... varargs best-effort. Strings passed to C are CStrings owned by the call frame — the C side must not retain them.

!

Safe by construction

Every foreign call goes through a single unsafe trampoline. The runtime never dereferences a raw pointer by accident — ffi_read/ffi_write take an explicit offset and operate one byte at a time. Symbol/library failures and unmarshalable types return Runtime("ffi: ...") errors, never a panic.

%

Debug / release notes

Float return values work via a second -> f64 trampoline; float-by-value arguments aren't supported in this build (full libffi support is deferred). Allocations from ffi_alloc/ffi_string_to_cstr are tracked so ffi_free releases them with the correct layout.

Memory-mapped files & zero-copy I/O shipped

Map a file and read it without loading it into RAM. A 4 GiB PCAP costs only the OS page cache for touched pages plus slice metadata.

Zero-copy by design

mmap_slice returns an Arc<MmapHandle> view that keeps the mapping alive — slices outlive mmap_close (which is just a convenience no-op). Single-byte indexing reads directly from the mapped page on both backends; range slicing, binary pattern matching over slices, and mmap_lines* work on the interpreter. mmap_lines yields owned strings (only safe way to iterate); use mmap_lines_off for true zero-copy line offsets.

Async I/O & futures shipped

async fn returns a deferred future whose body runs on the first await. http_get_async and tcp_probe spawn real Tokio tasks and return a pending future; await resolves them via block_on. The runtime is lazily-started, so no special entry point is needed.

IO

How futures resolve

A future is Ready, Pending (a Tokio JoinHandle — block_on(handle.await)), or Deferred (— an async fn whose body runs on the interpreter thread on first await and caches as Ready). await outside any "async context" just resolves the value, and a non-future passes through unchanged.

vm

VM behaviour

The VM compiles async fn to a regular Closure — the body runs synchronously on call (no interpreter to drive a deferred body), so await on the result is a no-op. Real async I/O returns a Value::Future and Op::Await blocks on it. await for / select fan-out is a follow-up.

Failure & cancellation

A panic inside a task surfaces as Runtime("await: task failed: <join error>"). Blocking on the interpreter thread doesn't stall the multi-thread runtime, and dropping a pending future aborts nothing eagerly — await is the only resolution point.

Raw sockets & packet forging shipped

Build packets as pure computation with no privileges, then send them if you have CAP_NET_RAW (or Administrator). Checksums are computed by the stdlib, not the kernel — forging malformed packets is intentional.

Builtins

All net_raw_ builtins work on both backends: net_raw_ipv4, net_raw_tcp, net_raw_udp, net_raw_tcp_syn, net_raw_csum, net_raw_send, net_raw_recv. Send/recv return a Result, so permission errors are handleable without try/catch. On Windows, send/recv return Err("... Windows raw-socket I/O not in this build") — the builders work everywhere.

Native protocol parsers shipped

Hand-written wire-format builders and parsers for DNS and TLS, plus PCAP via an optional feature. Everything is offline where possible and bounds-checked — malformed bytes produce Runtime("dns: ...")/"tls: ..." errors, never a panic.

53

DNS

Wire-format query builder and response parser with compression-pointer decoding. Records: A / AAAA / MX / TXT / CNAME / NS / PTR / SOA. Default resolver 8.8.8.8:53, no external DNS crate. Truncation is surfaced as truncated: true.

tls

TLS & PCAP

TLS decodes record + handshake layers for SNI (extension 0) and the cipher suite list, and walks concatenated DER certificate chains. PCAP reads offline captures and yields {timestamp, linktype, payload}; it's feature-gated and returns Err("pcap: not built ...") when off. Live capture (pcap_listen) and live TLS inspect are follow-ups.

Part 3 · Modules

Module system

Imports & exports are covered in Language features → Modules. The design is Python-style: import/from ... import/import *, pub/export marking, directory packages via init.rak, RAK_PATH search order, import-once caching, and circular-import support. Both backends resolve via the same modules.rs search path.

Error handling

Three pieces work together: Result/Option values, the ? operator, and try/catch/raise. Native systems code — FFI, mmap, net_raw — converts std::io::Error/OS errors into RakError::Runtime, never panicking.

? unwraps an Ok/Some and short-circuits an Err/None out of the enclosing function (or into the nearest try). raise throws any value; catch e binds it. Lexer and parser errors carry line/column, and rakc check emits them in an IDE-friendly form.

Resource cleanup is automatic

RAII everywhere: Arc<MmapHandle>, Arc<Mutex<TcpStream>>, and ForeignLib drop handlers call munmap/dlclose/FreeLibrary/shutdown for you. The explicit mmap_close/tcp_close/lib.close calls are convenience + early release, never required for safety.

Strings & arrays

Built-in helpers operate on strings, arrays, and maps. They're plain functions, not methods, so they work on both backends.

Interpolation

f"..." interpolates {expr} inline. fmt is the same idea with explicit format specifiers.

JSON

json_parse returns native arrays, maps, ints, floats, bools, and nil. json_stringify serializes back. Real round-tripping, no hand-rolling.

Concurrency

spawn launches a thread, thread_join waits, and channel() gives a sender/receiver pair. TCP networking is built in; for concurrent I/O prefer the async runtime (§ Async & futures).

Bytecode VM

Same language, two runtimes. The VM compiles the AST to a stack-based bytecode chunk and runs it — about 6× faster than the tree-walker on compute-heavy scripts. The unsupported features below fail fast with VM does not support ... rather than producing wrong results.

Run it

rakc bench bench.rak prints both timings. The VM supports functions, recursion, arrays/tuples/maps, indexing, match, interpolation, regex literals, the pipeline, macros, FFI, mmap, async I/O natives, and raw-socket builders.
